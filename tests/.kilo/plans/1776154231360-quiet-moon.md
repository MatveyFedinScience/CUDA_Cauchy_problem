# Plan: Добавить флаг для симуляции по потенциалу или силовым полям

## Цель
Добавить CLI-флаг `--forces`, позволяющий выбрать режим симуляции:
- **Режим потенциала (по умолчанию)**: генерируется Perlin шум для V (noise_modern.ppm grayscale), градиенты численно на лету из текстуры V, ускорение = -∇V.
- **Режим силовых полей**: генерируются независимые Perlin шумы для F_x и F_y (forces_modern.ppm: R=0, G=F_y, B=F_x), загружаются как текстуры, ускорение = (F_x, F_y) напрямую (dPhi_dx = -F_x, чтобы dvx/dt = F_x).

В силовом режиме potential=0 (энергия = кинетическая). Нормализация изображений как в PPM_C ([-1,1]→[0,255]). Силы = 0 вне круга.

## Изменяемые файлы
- `main.cu`: парсинг аргументов, новый kernel `compute_gradients_kernel`, функция `savePPM_forces`, создание текстур Fx/Fy при `--forces`, установка `g_use_forces`, освобождение ресурсов.
- `potentials.cuh`: объявления `d_FxTex`, `d_FyTex`, `g_use_forces`; модификация `potential` (if forces return 0) и `gradient_potential` (if forces: dPhi = -texF * IN_CIRCLE?).

Другие файлы не трогаем.

## Потенциальные проблемы
- Диапазон F ~ NOISE_SCALE * [-1,1] * IN = [-0.25,0.25], нормализация `(F+1)*0.5` → [0.375,0.625] серый, видимый.
- Энергия в forces: pot=0, проверка на kinetic conservation (из-за RK4 ok).
- Граница: F=0 outside via generation *IN_CIRCLE.
- Ускорение: ~4x меньше tex2D вызовов в integrator.
